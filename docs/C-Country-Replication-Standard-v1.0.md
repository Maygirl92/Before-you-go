# Before You Go — 国家板块复用标准 v1.0

状态：德国板块基线总结与后续国家复制规范  
日期：2026-09-08  
适用范围：在不改变 `Before You Go` 核心产品逻辑的前提下，将德国板块扩展为法国、意大利、西班牙等新的欧洲国家板块。

---

## 0. 文档定位与来源优先级

本文件总结德国板块已经形成的可复用标准，并把“跨国家不变的产品规则”“每个国家必须重新配置的内容”和“德国特例”分开。

它不是德国现有两份规范的替代品。发生冲突时按以下顺序处理：

1. `docs/A-Build-PRD-v2.1.md`：产品行为、页面、交互、数据字段、校验、视觉系统和指标。
2. `docs/B-Curation-Handbook-v2.1.md`：词表、配额、纳入规则、文案规范、策展流程和样本结构。
3. 目标国家的 `config.json`：该国家实际启用的地区、时期、子标签、颜色、品牌和配额。
4. 目标国家的 `works.json`：已经人工确认并可发布的最终作品记录。
5. 本文件：跨国家实施方法、交付门槛和德国经验。

任何冲突都必须先记录和裁决，不能通过前端硬编码、放松校验或静默修改内容来解决。

## 1. 复用模型：固定核心、国家配置、国家内容

每个国家板块由三层组成。

| 层级 | 跨国家是否复用 | 内容 |
|---|---:|---|
| 产品核心 | 完全复用 | 信息架构、五类筛选、筛选逻辑、梯队结构、卡片交互、URL 状态、响应式规则、指标、校验机制 |
| 国家配置 | 复制结构，重做取值 | 国家名称、slug、地图颜色、地区、历史时期、子标签、地区配额、来源池 |
| 国家内容 | 不复用数据，只复用格式 | 候选、提及证据、最终作品、中文文案、封面与来源 |

### 1.1 跨国家永久不变

- 品牌字标：`Before You Go`
- 品牌不设中文产品名。
- Slogan：`在这里，背起精神行囊`
- 目的地优先、以作品帮助理解地方的产品定位。
- 五类筛选：媒介类型、理解主题、创作视角、地区、时间成本。
- 三个梯队及其固定顺序：`必读之选`、`余力之选`、`归来之后`。
- 卡片式纵向作品流；不改为海报网格、排行榜或评分列表。
- 同一筛选面内是 OR；不同筛选面之间是 AND。
- 每个筛选状态可通过 URL 分享。
- 所有内部状态和 URL 使用稳定英文 slug；中文展示值不能充当 key。
- 母类主题固定为五类：`历史与记忆`、`社会与日常`、`地方与空间`、`身份与传统`、`艺术与文化`。
- `tier` 是默认分组与主排序，不是筛选面。
- `theme_tags` 只展示，不参与筛选；筛选使用 `theme_main`。
- 不提供账号、收藏、看过状态、评分、评论、社交、UGC、观看或购买链接、预订或行程功能。

### 1.2 每个国家必须重新建立

- 国家 slug、中文名、原文名和地图位置。
- 国家地图正面色与侧面色。
- 地区词表和 `region_primary` 配额。
- 历史时期词表。
- 国家相关的子标签及其 `home_theme`。
- 候选来源池，尤其是该国的文化机构、学术资源、奖项、本地媒体与中文出版社。
- 候选作品、每条来源证据、最终作品和全部中文文案。
- 与当地相关的 `on_the_ground` 事实。
- 该国实际可获得的中文译本或中文字幕状态。
- 封面及每张封面的合法来源、来源页面和人工核对结果。

### 1.3 不能复制为欧洲通则的德国特例

- 德国的地区词表，例如 `柏林`、`鲁尔区与莱茵兰`、`萨克森`。
- 德国的历史时期，例如 `魏玛`、`分裂时期`、`转折与统一`。
- 德国来源池中的 bpb Filmhefte、Goethe-Institut、Deutsche Kinemathek 等具体机构。
- 德国数据中的柏林占比、萨克森缺口以及德国现有 58 部作品的数量分布。
- 德国特有子标签。子标签可以跨国家复用，但必须先确认它在新国家确实有解释力。

## 2. 产品体验标准

### 2.1 用户任务

用户带着旅行时间、兴趣、媒介偏好或希望理解的地区进入页面，通过筛选快速缩小作品范围，并能理解每部作品为什么与这个目的地有关。

页面首先回答三个问题：

1. 这部作品是什么。
2. 它为什么值得在这次旅行前后接触。
3. 它与当地什么历史、空间或日常经验对应。

### 2.2 国家页面结构

固定顺序为：

1. 品牌页眉。
2. 国家 Hero：`DESTINATION · NN`、国家中文名、国家原文名。
3. 五类筛选。
4. 当前结果数与排序器。
5. `必读之选`、`余力之选`、`归来之后` 三个可展开/收起的作品区。
6. 每个区内按规则排序的纵向卡片流。

德国当前页面默认展开第一个梯队，后两个梯队收起。新国家应复用这一默认状态，除非用户研究证明需要调整。

### 2.3 卡片信息层级

收起状态显示：

- 封面。
- 中文标题；为空时回落到原文标题。
- 较小、斜体的原文标题。
- 创作者、年份、创作者国家。
- 媒介、时间成本、创作视角。
- 作品子标签。

展开状态增加：

- `简介`
- `值得之处`
- `对应之处`，仅在 `on_the_ground` 有值时显示。
- 与梯队有关的解释，仅在数据有值时显示。

`cn_edition` 用于数据审核和可用性判断，不在当前卡片中渲染。空字段的标题和空白容器都不得显示。

### 2.4 展开与收起

- 单次点击或轻触完成；任何位置都不使用双击。
- 梯队和作品卡片都要保留明确的 `aria-expanded`、`aria-controls` 和键盘焦点样式。
- 展开和收起要有短促、轻微弹性的高度过渡。
- 移动端只对布局高度做动画，不叠加大面积透明度和位移动画，以避免回弹卡顿。
- 尊重 `prefers-reduced-motion`，将动画缩短至近乎即时。
- 展开卡片时保留筛选状态与滚动位置。

## 3. 国家数据包标准

扩展到多国家时，建议将每个国家整理为独立数据包，公共前端只读取同一接口：

```text
data/
  shared/
    theme-colours.json
    global-vocabularies.json
  countries/
    de/
      config.json
      candidates.json
      mentions.json
      works.json
      cover-overrides.json
    uk/
      config.json
      candidates.json
      mentions.json
      works.json
      cover-overrides.json
```

德国与英国现已使用该国家数据包结构。历史候选和提及文件仍需在证据链迁移时按国家归档；共享页面只读取 `data/countries/{destination}/config.json` 与 `works.json`。

### 3.1 三张表的职责

| 数据集 | 一行代表 | 职责 | 是否进入前端 |
|---|---|---|---:|
| `candidates` | 一个原始候选 | 保存候选标题、来源线索、初步媒介判断和处理状态 | 否 |
| `mentions` | 某作品在某一来源中的一次独立提及 | 保存证据、来源类型、链接、日期和纳入判断依据 | 否 |
| `works` | 一个已经归一化并批准发布的作品 | 为页面提供完整、可验证、可筛选的最终记录 | 是 |

三张表可以先由表格维护再导出 JSON，不要求数据库。扩大到多个国家后仍保留三表逻辑；是否引入数据库只由协作规模和数据量决定，不能为了“技术完整”提前引入 CMS、账号或权限系统。

### 3.2 标识符规范

- 目的地：ISO 风格稳定小写 slug，例如 `de`、`fr`。
- 作品：`{destination}-{medium}-{work-slug}`，例如 `de-screen-...`。
- 词表：英文 slug 作为值，中文标签在配置中映射。
- 已发布 slug 不随中文翻译、标题修订或展示标签变化。
- 同一真实作品跨国家出现时，应增加一个跨国家实体标识层；在建立该层前，不通过标题字符串自动合并。

## 4. `works` 记录规范

下面是德国 v2.0 页面当前实际消费的数据接口。新国家必须使用相同字段语义。

| 字段 | 类型 | 必填规则 | 说明 |
|---|---|---|---|
| `id` | string | 必填 | 稳定英文 ID |
| `destination` | string | 必填 | 国家 slug |
| `tier` | enum | 必填 | `before-you-go` / `if-you-have-time` / `after-you-return` |
| `tier_label` | string | 必填 | 配置映射出的中文展示标签 |
| `medium` | enum | 必填 | `screen` / `book` / `music` |
| `medium_label` | string | 必填 | `影像` / `书籍` / `音乐` |
| `medium_sub` | enum | 必填 | 见 §5.1 |
| `medium_sub_label` | string | 必填 | 对应中文展示标签 |
| `title_zh` | string/null | 可选 | 有已核实的通行中译名时使用；否则页面主标题回落到 `title_original` |
| `title_original` | string | 必填 | 原文标题 |
| `title_alt` | string[] | 必填，可空数组 | 其他可靠标题，不用于模糊自动合并 |
| `creator` | string | 必填 | 创作者展示字符串 |
| `creator_country` | string | 必填 | 创作者国家展示值 |
| `year` | integer | 必填 | 首次出版、发行或首映年份 |
| `extent` | string/null | 影像与音乐必填 | 片长、页数或音乐时长的展示字符串 |
| `music_style` | string/null | 仅音乐可有值 | 非音乐必须为 null |
| `regions` | string[] | 必填，1–3 个 | 参与地区筛选；均须来自国家配置 |
| `region_primary` | string | 必填 | 必须属于 `regions`；地区最低配额只按此字段统计 |
| `periods` | string[] | 必填 | 国家特有历史时期，仅来自配置 |
| `theme_main` | string[] | 必填，1–2 个 | 五个固定母类主题；用于筛选，不在卡片显示 |
| `theme_tags` | string[] | 必填，1–4 个 | 展示型子标签，不参与筛选；一个准确标签优于虚构第二个标签 |
| `lens` | enum | 必填 | `local` / `outsider` / `diaspora` |
| `lens_label` | string | 必填 | 对应中文展示值 |
| `time_cost` | enum/null | 条件必填 | 音乐必须为 null；非音乐必须有值 |
| `time_cost_label` | string/null | 与 `time_cost` 同步 | 对应中文展示值 |
| `summary` | string | 必填 | `简介` 文案 |
| `worth` | string | 必填 | `值得之处` 文案 |
| `on_the_ground` | string/null | 可空 | `对应之处`；只写可核对事实和地点 |
| `tier_reason` | string/null | 条件字段 | 仅 `after-you-return` 可有值；空则不显示 |
| `cn_edition` | object | 必填 | 中文译本、中文字幕或不适用状态 |
| `cover` | URL/null | 发布前应有值 | 浏览器直接读取的封面 URL；不包含 API token |
| `cover_source` | string/null | 有封面时必填 | 封面来源名称 |
| `cover_source_url` | URL/null | 有封面时必填 | 可追溯的来源页面 |
| `sort_order` | integer | 必填 | 同一国家内唯一；梯队内默认次序 |

### 4.1 跨字段硬规则

以下任一不满足都属于 schema 错误，开发和生产都必须失败：

1. `regions` 有 1–3 个值，且全部存在于国家配置。
2. `region_primary` 有值并属于 `regions`。
3. `theme_main` 有 1–2 个值；`theme_tags` 有 1–4 个；值均存在于配置。
4. `lens`、`time_cost`、`medium`、`medium_sub`、`tier`、`periods` 均为合法值。
5. 当且仅当 `medium == "music"` 时，`time_cost` 为 null。
6. 影像和音乐必须有 `extent`。
7. `cn_edition.status` 必须适用于该媒介。
8. 书籍为已出版中文译本时，出版社和译者不能为空。
9. 只有 `after-you-return` 可以拥有非空 `tier_reason`。
10. 同一国家中 `sort_order` 唯一。
11. 只有音乐可以拥有非空 `music_style`。
12. `title_original` 必须非空；`title_zh` 可缺省或为 null，此时页面回落到原名且不重复显示副标题。
13. `quotas.capital_max_share` 可显式为 null，但国家配置必须同时记录理由。

不得添加“`theme_tags` 必须被 `theme_main` 覆盖”的规则。子标签的归属色来自自身 `home_theme`，与作品的 `theme_main` 独立。

### 4.2 中文版本状态

- 书籍：必须是已出版的中文译本才标为可得，并记录出版社与译者。
- 影像：记录可合理获得的中文字幕状态。
- 音乐：不适用；时间成本筛选中也排除音乐，并明确显示被排除的数量。

## 5. 受控词表

### 5.1 跨国家固定词表

| 维度 | 稳定值 |
|---|---|
| `medium` | `screen`、`book`、`music` |
| `medium_sub` | `film`、`documentary`、`series`、`novel`、`nonfiction`、`essay`、`poetry`、`album`、`single` |
| `lens` | `local`、`outsider`、`diaspora` |
| `time_cost` | `one-evening`、`several-evenings`、`long-haul`；音乐为 null |
| `tier` | `before-you-go`、`if-you-have-time`、`after-you-return` |
| `theme_main` | `历史与记忆`、`社会与日常`、`地方与空间`、`身份与传统`、`艺术与文化` |

`series` 是合法影像子类型，`poetry` 是合法书籍子类型，不得因旧版决策或旧代码而排除。

### 5.2 国家局部词表

`regions`、`periods` 和 `theme_tags` 必须在策展开始前建立草案，在首轮候选完成后复核，但不能为了让配额通过而随意合并或删除。

- 地区既要支持旅行者理解，也要足以区分作品视角。
- `region_primary` 必须表达作品最主要的地域落点。
- 全国性作品使用统一的全国标签，不为每国另造同义词。
- 时期词表服务理解，不追求学术史分期的无限细化。
- 子标签优先复用已有跨国家概念；只有现有标签确实无法表达时才增加。
- 每个子标签必须声明一个固定 `home_theme` 和对应颜色。

## 6. 策展准入标准

### 6.1 标准通道

作品必须同时满足：

- 来自不同 `source_type` 的至少 2 次独立提及。
- 其中至少 1 次来自机构、学术或奖项来源。
- 能通过“可标签化测试”和“旅行指南差异测试”。

### 6.2 补充通道

用于修补明确的地区、视角、主题或媒介缺口，必须同时满足：

- 至少 3 次独立提及。
- 至少 1 次来自本地来源或新闻媒体。
- 明确记录所填补的维度和值。
- 经过人工批准。
- 仅有平台来源永远不够。
- 补充通道占最终数据不超过 30%。

### 6.3 排除条件

- 只是在该国取景，作品本身与当地没有实质关系。
- 只有创作者国籍关系，没有明确文化关系。
- 主要因为流行度或评分而推荐。
- 地点关系无法验证。
- 来源不可靠或事实错误。
- 与已收录作品高度重复，且没有新的视角。

语言、创作者国籍和取景地都不能单独成为收录理由。

### 6.4 来源设计

每个国家都应建立六类来源池：

1. `institution`：电影资料馆、国家文化机构、公共教育资源。
2. `academic`：地区研究、文学、电影与文化研究课程和论文。
3. `award`：与作品质量和国家文化相关的可靠奖项。
4. `press`：该国主要报刊与文化媒体。
5. `local`：当地创作者、居民和具有本地经验的策展者。
6. `platform`：只作为补充线索，不能单独完成准入。

书籍候选池以中文出版社和已出版中文译本为核心，不以英语世界书单替代中文可得性判断。评分不进入数据结构和产品界面。

## 7. 文案标准

所有中文用户可见字符串必须原样保存，不翻译、不润色、不自动缩写。代码、注释、标识符和 slug 使用英文。

### 7.1 数字和格式

- 年份和日期使用阿拉伯数字。
- 年龄、时长、数量、序数在正文中按中文表达规则处理。
- `on_the_ground` 中多个地点或事实用 ` · ` 分隔。
- 正文不使用 Markdown。

### 7.2 `summary`

- 约 150 个汉字。
- 是叙事性简介，不是宣传文案，也不是数据库摘要。
- 尽量包含时代、人物或情境、作品的核心机制和必要名字。
- 不进入逐场景复述。

### 7.3 `worth`

- 约 150–250 个汉字。
- 以旅行者为理解主体，说明读、看或听完以后能认出、理解或重新看见什么。
- 必须提供普通旅行指南不能提供的解释。
- 不做榜内排名，不反复使用“拍的是”“写的是”，不加入聊天式旁白。
- 阅读或观看难度可以在这里诚实说明。

### 7.4 `on_the_ground`

- 只写可核实的地点、事实和对应关系。
- 不写命令式行程建议、传闻或需要用户现场验证的说法。
- 没有可靠内容时为 null，并完全省略页面区块。

### 7.5 `tier_reason`

- 解释为什么作品属于 `归来之后`。
- 梯队的条件性说明保留为人写的文案，不转成动态算法。

## 8. 梯队、筛选与排序标准

### 8.1 梯队判断

策展者依次评估：

1. 落地对应：与旅行中可感知的地点、制度、历史或日常是否直接对应。
2. 解释力：是否能改变用户对该国的理解。
3. 成本：时间、知识门槛和观看或阅读负担是否合理。

音乐因为没有时间成本筛选，主要依据前两项判断。

### 8.2 筛选逻辑

- 同一筛选面内任一选中值命中即可。
- 不同筛选面必须同时满足。
- 地区筛选匹配 `regions` 中任一值，不只匹配 `region_primary`。
- 每个选项的实时数量按“保留其他筛选，暂时忽略本筛选面”计算。
- 数量为 0 的选项保留原位置、变灰并禁用；已经选中的值永远不能变成不可操作。
- 当前选中条件要以中文标签显示，不能泄露英文 slug。
- 清除筛选恢复默认结果和 URL。

URL 参数保持稳定：

- `medium`
- `theme` 对应 `theme_main`
- `lens`
- `region`
- `time` 对应 `time_cost`
- `sort`

数组值必须以确定性顺序序列化，保证同一状态生成同一 URL。

### 8.3 排序

三大梯队的顺序永远不变；排序只改变各梯队内部：

- 推荐顺序：`sort_order`。
- 时间成本：由短到长，音乐排最后。
- 年份：从新到旧。
- 最近新增：按 `published_at`；没有该字段时必须禁用，不得伪造时间。

### 8.4 零结果

零结果不能只显示通用空白提示。页面应指出造成限制最强的条件，并提供一次点击即可移除的建议；同时记录完整筛选状态用于分析。

## 9. 视觉系统

### 9.1 视觉方向

整体是安静、编辑化、可阅读的旅行文化工具：浅灰页面底、白色作品卡、细分隔线、低饱和主题色、宽松但不过度铺满的版心。视觉重点是标题、作品关系和筛选结果，不使用评分星级、商业平台式大按钮或装饰性阴影。

### 9.2 字体系统

德国当前实现已经形成以下跨端基线：

- 中文 UI 与正文：`Noto Sans SC`，后备为苹方、微软雅黑和系统无衬线。
- 中文国家名、梯队名、作品标题与结果标题：`Noto Serif SC`，后备为宋体系统字体。
- 原文标题：Georgia 或同类 Latin serif，斜体，比中文标题小一级。
- 品牌字标：Arial 或中性 Latin sans，英文大写展示、增加字距。
- 正文仅使用 regular 与 medium 两档，不在正文使用粗黑体。

字体必须由同一套加载策略提供给桌面和移动端；不能让手机依赖设备随机回退字体。

### 9.3 颜色系统

规范配置中的基础色为：

| Token | 色值 | 用途 |
|---|---|---|
| `page` | `#F1F2F2` | 页面浅灰底色 |
| `card` | `#FFFFFF` | 卡片 |
| `rule` | `#F0EEE8` | 分隔线 |
| `main` | `#241F18` | 主文字 |
| `muted` | `#6E6A60` | 次要文字 |
| `faint` | `#8A8578` | 弱化文字与数量 |

五个母类主题使用固定的浅底色和同色相深文字：

| 母类主题 | 填充 | 文字 |
|---|---|---|
| `历史与记忆` | `#DCE7F3` | `#2C4763` |
| `社会与日常` | `#DDEBD6` | `#3A5531` |
| `地方与空间` | `#F7E7C4` | `#6B4712` |
| `身份与传统` | `#F7DBDD` | `#7A3841` |
| `艺术与文化` | `#E4DDEF` | `#493869` |

为了提高可读性，只能在保持色相关系的前提下调整；当前浅色填充配深色文字的对比逻辑中，进一步变浅填充会提升对比度，不应通过把填充变深来“增强”。

### 9.4 版心与桌面尺寸

德国当前稳定实现使用：

- 主版心最大宽度 980px。
- 桌面两侧总留白至少 72px，页面内部再留 10px。
- 页面底部留白约 100px。
- 筛选行采用约 150px 标签列加弹性选项列。
- 每行最小高度约 58px。
- 梯队之间约 48px，作品卡之间约 12px。
- 桌面卡片封面列约 128px，卡片最小高度约 158px。
- 卡片为白底、1px 细边线，不使用阴影。

这些数值是德国页面经过桌面和手机调试后的基线。新国家先原样复用，只在真实内容导致溢出时通过响应式规则处理，不按国家单独缩放整个设计。

### 9.5 移动端

小于 640px 时：

- 页面左右边距 14px，内容最大宽度 520px。
- 卡片内边距和列间距约 12px。
- 封面固定为 96×144px、2:3 比例，不能被文本列挤窄。
- 作品标题约 19px，收起时最多两行。
- 原文标题收起时最多一行。
- 收起状态隐藏子标签和视角标签，展开后再显示完整信息。
- 梯队标题约 24px。
- 展开/收起控制与作品数量使用同一字体基线和字号，文字与图标垂直对齐。
- 避免 opacity 与 transform 同时作用于整组长列表，减轻移动浏览器的合成卡顿。

### 9.6 国家地图视觉

- 地图块不加轮廓、不加投影、不加装饰圆点。
- 正面与侧面颜色按国家配置，不通过明暗模拟厚度，而以不同色相区分。
- 德国正面为 `#C6E3E8`，侧面为 `#EAF0A4`；它们是德国签名色，不自动复制给其他国家。
- 桌面 hover 或触屏 tap 揭示简介；进入国家必须使用明确按钮。
- hover 上移 10px，露出下面的第二个多边形。

### 9.7 封面

- 影像优先 TMDB 官方海报。
- 书籍优先中文已出版译本封面，并由中文出版社、图书馆或可靠书目页面人工确认。
- 音乐优先 Cover Art Archive。
- 可以先本地运行解析脚本，将最终公开 URL 写入 `cover`；浏览器端不得携带 TMDB token。
- 同时记录 `cover_source` 与 `cover_source_url`。
- 禁止自行抓取未知来源图片、上传来源不明的第三方文件或仅凭相似标题自动确认。
- 自动匹配结果必须由人核对作品、年份、版本和媒介后才能写回。

## 10. 配额系统

配额是可执行规则，不是口头目标。配额数值可因国家内容生态调整，但每一维都必须有明确数字，并写入国家 `config.quotas`。

每个国家至少定义：

- 外来视角最低数。
- 移民与跨文化视角最低数及其中影像最低数。
- 首都或单一最大城市的最高占比，按 `regions` 任意命中统计。
- 全国性作品最高占比。
- 五个母类主题各自最低数。
- 首都与全国以外各地区最低数，按 `region_primary` 统计。
- 当代作品最低数，并明确定义年份门槛。
- `一个晚上` 最低数。
- 补充通道最高占比。

配额设计原则：

1. 先根据国家地理、历史和候选池设计，再开始最终选片。
2. 不把德国的具体数值机械复制到人口、地区结构和媒介供给不同的国家。
3. 不为使数据通过而降低配额；缺口必须在报告中保持可见。
4. 开发模式配额不满足时警告；生产模式默认失败。若策展负责人批准带缺口发布，必须在国家配置中显式记录临时例外，并继续打印完整缺口。
5. schema 错误在两种模式都必须失败。

## 11. 完整工作方法

以下流程是每个新国家的标准生产线。各阶段有明确产物和退出条件。

### 阶段 0：建立国家简报

产物：国家范围说明、用户旅行场景、地区草案、时期草案、来源池和初始配额。

退出条件：

- 国家边界和本版本不做什么已经写清。
- 地区能覆盖全国且不会只围绕首都。
- 五个母类主题保持不变。
- 责任人同意配额设计。

### 阶段 1：建立配置

产物：国家 `config.json`。

依次完成：

1. `brand` 复用全局值。
2. `destination` 填写 slug、中文名、原文名、地图颜色。
3. 录入梯队、媒介、视角和时间成本的固定词表。
4. 录入国家地区和时期。
5. 录入子标签、`home_theme` 和颜色。
6. 录入完整 `quotas`。

退出条件：配置自身通过唯一性、引用关系和颜色对比检查。

### 阶段 2：建立候选池

产物：`candidates.json` 或同结构工作表。

方法：

- 从机构、学术、奖项、新闻、本地和平台六类来源搜集。
- 书籍优先中文出版社与中文译本目录。
- 此阶段可以宽进，但要记录来源 URL、日期、原始标题和初步媒介。
- 不因评分、榜单排名或社交热度直接进入最终数据。

退出条件：候选覆盖预定地区、主题、视角和媒介，能看出主要缺口。

### 阶段 3：逐条记录提及证据

产物：`mentions.json`。

- 一部作品在一个独立来源中的证据是一行。
- 记录 `source_type`、来源名称、URL、发布日期或访问日期、支持的判断和必要摘记。
- 同一内容的转载不算两个独立来源。
- 平台帖子可以提供线索，但不能替代机构、学术、奖项或本地证据。

退出条件：每个拟收录作品都能清楚判断走标准通道还是补充通道。

### 阶段 4：准入与去重

产物：批准、拒绝、待查三类清单及理由。

- 执行 §6 的标准通道或补充通道。
- 做作品实体去重、不同版本辨认和标题归一。
- 执行国家关系、可标签化和旅行指南差异测试。
- 把填补的配额维度记录下来，不能只写“整体需要”。

退出条件：每个进入 `works` 的作品有可追溯证据和人工批准。

### 阶段 5：结构化与写作

产物：完整 `works.json` 草案。

推荐顺序：

1. 基础书目或影视元数据。
2. 媒介、地区、时期、母类主题、子标签和视角。
3. 中文版本状态。
4. `summary`。
5. `worth`。
6. `on_the_ground`。
7. 梯队和必要的 `tier_reason`。
8. `sort_order`。

退出条件：每条记录都有完整字段，中文文案经过事实与风格双重审核。

### 阶段 6：梯队与配额复核

产物：梯队表和配额差距报告。

- 按落地对应、解释力、成本三项分梯队。
- 先看结构性缺口，再决定是否通过补充通道增加作品。
- 不通过移动标签、修改 primary 或降低数字来掩盖缺口。
- 已知但尚未填补的缺口必须保持显眼。

退出条件：所有 schema 规则通过；配额缺口已经解决或得到明确的产品发布裁决。

### 阶段 7：封面处理

产物：每部作品的 `cover`、`cover_source`、`cover_source_url` 及人工核对记录。

方法：

1. 在本地通过 API 或公开封面服务生成候选。
2. token 只放 `.env.local`，永不提交到 Git，也不进入前端 bundle。
3. 人工核对中文译本、电影年份、音乐发行版本。
4. 将确认后的公开 URL 写入 `works.json`。
5. 构建后检查图片域名、加载失败和移动端裁切。

退出条件：无来源不明封面；来源可追溯；页面不需要运行时密钥。

### 阶段 8：实现国家页面

产物：国家路由、数据加载、筛选、排序、URL、卡片交互和响应式页面。

实现顺序：

1. 数据加载、梯队和卡片。
2. 五类筛选与 URL 序列化。
3. 国家地图入口。
4. 页眉与字体。
5. 封面。
6. schema 校验、配额校验与差距报告。

退出条件：页面不包含该国家硬编码词表；切换数据包即可复用组件。

### 阶段 9：测试与人工验收

自动测试至少覆盖：

- 同面 OR、跨面 AND。
- 地区匹配 `regions` 任一值。
- 筛选数量排除自身筛选面的算法。
- 零数量、已选值和清除行为。
- URL 序列化、反序列化与刷新恢复。
- 梯队固定顺序和各排序模式。
- 全部 schema 硬规则。
- 代表性配额及完整差距报告。
- 中文 label 与英文 slug 的映射，防止界面显示英文内部值。

人工验收至少覆盖：

- Chrome、Safari；桌面和真实手机。
- 100% 浏览器缩放下的版心、字号和密度。
- 长中文标题、长原文标题、无封面、无 `on_the_ground`。
- 筛选后展开卡片时的滚动位置。
- 梯队展开/收起在移动端的流畅度。
- 封面 2:3 比例、书籍 contain 与影像 poster 展示。
- 键盘操作、焦点、读屏标签和减少动画模式。
- 所有中文字符串与最终数据逐字一致。

### 阶段 10：发布

德国当前使用纯静态 Next.js 导出和 GitHub Pages：

```bash
npm ci
npm test
npm run build
```

发布规则：

- production 是部署构建默认校验模式。
- schema 或生产配额失败时不得生成可发布版本。
- GitHub Pages 的 base path 通过环境变量提供，不在组件内写死。
- 合并到 `main` 后由 GitHub Actions 构建并发布。
- 发布后抽查国家首页、带筛选 URL、刷新恢复、图片和移动端。

### 阶段 11：发布后复盘

至少观察：

- 有效收敛率目标 40%。
- 空转率低于 15%。
- 卡片展开率目标 45%。
- 平均每次访问展开至少 3 部作品。
- 激活率目标 60%。
- 每次零结果都记录完整筛选状态。

数据只用于判断筛选、标签和内容解释是否有效，不转化为评分、热门榜或个性化推荐。

## 12. 技术架构复用标准

推荐保持以下边界：

```text
国家数据包
  config + candidates + mentions + works
                │
                ▼
构建期校验
  schema + quota + gap report
                │
                ▼
共享领域逻辑
  filtering + counts + sorting + URL state
                │
                ▼
共享 UI
  CountryPage + Facets + TierSection + WorkCard
                │
                ▼
静态国家路由
  /de  /uk  /fr  /it ...
```

原则：

- 内容与配置在 JSON；页面不依赖数据库、CMS 或运行时 API。
- 封面解析发生在本地或构建前，公开页面只消费 URL。
- 领域逻辑使用稳定英文值，显示层通过配置得到中文标签。
- 国家组件不复制；新增国家主要增加数据包和地图配置。
- 校验先于页面构建。
- 所有国家共用测试套件，并为每国追加配额测试样本。

## 15. 复制下一个国家前必须处理的德国遗留

这些项目不是新国家的内容任务，而是共享基础设施任务。应先处理，避免问题成倍复制。

### P0：统一数据 schema 与校验器

当前网页消费的是 v2.0 `works.json`，但 Python 模型和 SQLite schema 仍保留旧字段与旧枚举。现有 Python 测试没有校验 58 条实际作品。必须选择 v2.0 为唯一接口，更新或移除旧层，并让构建直接校验真正发布的数据。

### 已完成：配额配置与构建期报告

英德国家配置均已包含 `config.quotas`，构建前会执行 schema、配额与可读差距报告。当前发布例外通过显式 `_enforced` 状态记录，不改变原始配额目标。

### P0：补回策展证据链

当前 `data/candidates.json` 与 `data/mentions.json` 均为空。德国最终作品已经完成，但仓库内无法按三表规则复核来源证据。需要从策展工作底稿迁回，不得根据 `works.json` 反向虚构来源。
